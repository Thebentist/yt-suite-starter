# write-script

Launch the `yt-scriptwriter` agent (Agent tool, `subagent_type: "yt-scriptwriter"`) with a brief built from the steps below, then review what it returns before showing the user. Current requests from the user override defaults.

## Inputs to assemble for the brief
1. **Where the idea comes from**
   - Swipe concept: `research/<id>/<run>/swipe.json`, meaning the concept row (my_title, my_thumbnail, my_angle, mechanism) and its source video (url, title, multiple, baseline). Slug = a short kebab version of my_title.
   - Topic: the user's words; slug from the user or from the topic.
2. **Mode**: the host's preference in their rules file (`channels/<host>.json` → `rules`, usually `docs/host-rules.md`, "How they like to record"). The original host preferred `talking-points` (see `docs/ben-rules.md` "The talking-points loop"), and it is the default until the host says otherwise. Use `full` when the user asks for a full script, or when revising a script built from their recorded transcript.
3. **Host and voice** (two different things):
   - `host:<id>` is who is on camera (default: `suite.json` → `host`): `channels/<id>.json`. The host decides what may be said about the speaker; their rules file applies in full. Any channel gets the "nothing invented about the host" rule.
   - `voice:<id>` is whose speaking style the lines follow (default: the host). Available voices are the folders in `voice/` with a fingerprint: the host's own (after `/voice-learn`), `thebentist` (the original host: 103 transcribed videos, mostly unscripted, the best reference for natural spoken rhythm), `cleoabram` (Huge If True), `vsauce` (Michael Stevens), `altonbrown` (Good Eats). Evidence: `voice/<voice>/voice-guide.md`, `exemplars.md`, `profile.md` (if the guide is missing, the agent works from profile + exemplars + transcripts and says so). The reference voices' transcripts are not shipped; `/voice-learn <id>` rebuilds them.
   - `structure:<id>` borrows another creator's **architecture** while the lines stay in the voice (e.g. "Cleo Abram style in my voice" = `structure:cleoabram voice:<host>`). For `structure:cleoabram`: the full Huge If True build from `docs/huge-if-true-writing.md` (sections 0 to 4, 8, 11 and 20: the beat sheet with its % positions, the question stack, the vehicle and descent, the receipts, the skeptic beat, the reframe, the wonder toolkit, the four-move ending, the Cleo-to-host mapping, written for the original host "Ben") and the structural moves in `voice/cleoabram/voice-guide.md` ("How to borrow this voice for a different host"). Her physical cold open maps to whatever the host can do on camera (for a talking-head host: a narrated moment with animation). Retention rules still apply; where the two conflict, the host's rules and voice win. Structure variants of an existing script go in the same folder as `script-<structure>.md`, reusing its research and legal review.
   - When the voice isn't the host's own: borrow rhythm, sentence moves, how they explain and react, and their structure, but **never their trademarks** (catchphrases, sign-offs, show names, recurring bits: e.g. "huge if true", "and as always thanks for watching", Good Eats' named segments, the original host's "you know what to do"). The script must not present the host as that creator. For `voice:cleoabram` also read `docs/huge-if-true-writing.md` in full; for `voice:vsauce`, `docs/vsauce-layer.md`.
4. **The host's notes** verbatim.

## What the agent must produce (in `videos/<slug>/`)
- `packaging.md`: the title (plus 2 alternates in the same mechanism), the thumbnail brief, and the promise in one sentence. The first 30 seconds must deliver on exactly this.
- `beat-map.md`: for a swipe concept, run `node pipeline/script/source-transcript.mjs --url <source url> --out videos/<slug>/source`, read the `.beats.md`, and map the source's structure (hook type and length, when the title promise is confirmed, each open loop and where it closes, the payoff position as % of runtime, re-hooks). Then write the table **their beat / our beat / % of runtime**. Borrow structure only; no sentence of theirs survives into ours.
- `research-notes.md`: every fact and number with its source URL (WebSearch/WebFetch), the expert caveat, and a "don't say" list. Ask the host what an expert in their field would say is missing (the main session relays the question if needed; answers go to `docs/host-expert-notes.md`).
- `talking-points.md` (mode talking-points), following "The talking-points loop" (`docs/ben-rules.md`, the worked example) and bible section 21; **or** `script.md` (mode full) with sparse `[VISUAL: ...]` notes, never a shot list.
- `review.md`: the first-person lines list for the host's sign-off, the retention map (hook ≤0:30, title words by about 0:10, thumbnail promise confirmed by 0:15, a loop or re-hook about every 2 minutes, payoff after 80%, ending on a high note), the `node pipeline/script/retention-check.mjs <script>` PASS/WARN lines and the scored `docs/retention-checklist.md` table with line numbers plus its score line (NN/25, HARD fails; run before the voice checks), `node pipeline/voice/voice-check.mjs <script> --channel <voice>` output, `node pipeline/script/ai-tells.mjs --allow-fragments` output, a trademark check when the voice is another creator's (none of their catchphrases or bits appear), and anything unresolved.

## Structure sources (the agent reads these, in this order)
The host's rules file (`channels/<host>.json` → `rules`), the host's house-voice prompt (`channels/<host>.json` → `voice.style_prompt`, written in onboarding phase 2 from their transcripts; the worked example is `docs/style-prompts/bentist-measured.md`, measured from 80 of the original host's videos), `docs/huge-if-true-writing.md` sections 2, 9, 10, 11, 18, 19, 20, 21 (beat sheet, human-not-AI tells, algorithm fit, story spine and ending, Kallaway's framework and storytelling tips, Magic School Bus bar, talking points), `docs/youtube-playbook.md` sections 2 and 3, then `docs/retention-playbook.md` before the outline (the outline is the shock-scored high-shock points list; where Kallaway conflicts with the host's rules or the voice, its conflicts table says what to do instead; it names Ben, the original host, read it as the host) and `docs/retention-checklist.md` before the voice checks. Other creators in `reference/transcripts/` are for structure, never for the host's voice.

## The blind test (full scripts; you run the judges, the agent rewrites)
When the agent reports a quiz path (`videos/<slug>/blind/judge-prompt.md`):
1. Launch **two** fresh judges in the same message: Agent tool, `subagent_type: "general-purpose"`, `model: "sonnet"`, prompt: "Read <path>/judge-prompt.md and do exactly what it asks. Do not open any other file or search the web. Write ONLY the JSON array to <path>/verdict-a.json (or -b) with the Write tool, then reply done."
2. The first time for a voice (no `voice/<voice>/blind-control.md`), also run the control once: `node pipeline/voice/blind-test.mjs --script <script> --channel <voice> --type <type> --control self --out voice/<voice>/blind-control` and the same two judges on it; save their accuracies in `voice/<voice>/blind-control.md`. That's the noise floor.
3. `node pipeline/voice/blind-test.mjs --score <path>/key.json <path>/verdict-a.json <path>/verdict-b.json`. Pass: both under 60%, no paragraph caught by both, and within 15 points of the control. Otherwise send the caught paragraphs and the judges' reasons back to the agent (SendMessage). It rewrites the caught paragraphs **and sweeps every other paragraph for the same tells**: each round draws a new random sample, so untouched paragraphs get caught next time (learned on the wisdom-teeth proof run, where round 3 was caught on an outro and an objection paragraph never rewritten). Then regenerate with a new seed and judge again. From round 2 on, use `--n 16` so more of the script is sampled. Stop after 3 rounds and report where it stands, with the trend.
   **Keep the test fair.** The real half is topic-matched by default (the host's passages closest to the script's subject). For a story the host has never covered (a company, a case, a news event), add `--mask-names`: mid-sentence names become "[name]" on both sides. Learned on the kids-dental-chain script: one judge said it called paragraphs AI because they "serve the video's Small Smiles narrative" (every story paragraph was caught, 94%), while the other judge passed it at 59%. Read the judges' reasons for topic before believing a score.
4. Optional tell-harvester: one `model: "opus"` judge. Its score isn't the gate (it spots composed text even from real scripted creators), but its reasons name tells worth fixing.
5. Give the host `quiz.html` from the last round: their own ear is the real test.
6. **Know the ceiling** (wisdom-teeth proof run, 2026-09-28: 100 → 83/75 → 58/63 → 67/54 → 78/75 on a bigger 32-item quiz). After the big tells are gone, Sonnet judges still sort clean script from transcribed speech at 55 to 78%, all at low confidence, because what marks the real passages is transcription noise (misheard words, grammar slips, doubled words, live narration of footage) that a script must not fake. They even flagged a near-verbatim line of the original host as "engineered". So: 3 rounds maximum, never add fake disfluency, and then move to **the read test**: when the host records the script, `node pipeline/edit/transcribe.mjs --in <take>` and run `blind-test.mjs --script <transcript>.txt --channel <host> --type <type>` so their read (with its natural texture) is judged against their unscripted videos, plus `voice-check` on the transcript. That is the fair version of the test.

## Deliver a reading copy (always)
The host reads scripts on camera. `.md` files don't open in the side panel and the full script.md is hard to read, so for every finished script (and each variant): `node pipeline/script/read-copy.mjs videos/<slug>/script.md` and send the `-read.html` with SendUserFile (display: render). It shows only the spoken lines in big type with section timestamps; visual cues and optional demos sit behind toggles; `-read.txt` is the teleprompter version. Never paste the full script into chat.

## After the agent returns
Check that the files exist, that `type:` is declared, that review.md logs the passage ids each beat was modelled on, and that retention-check plus the retention checklist score, voice-check (with `--type`), ai-tells and the blind test actually ran (paste their headline numbers). Read the script's first 30 seconds yourself against `packaging.md`. Then show the user: the title, the thumbnail brief, the first 30 seconds verbatim, the beat outline (one line per beat), the voice-check score with its misses, the first-person lines needing sign-off, and the clinician question if one is open. For revisions ("doesn't sound like me"), relaunch the agent with the notes and tell it to go back to the transcripts first.

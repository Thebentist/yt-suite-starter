# Edit lessons (read before every edit; append after every review round)

Every mistake from a real edit, why it happened, and where the fix now lives, so the next video starts where this one ended. One line per lesson where possible. **Guard** = code now enforces it. **Rule** = a person (or Claude) must follow it. Newest at the top of each section. Source edit: `videos/bad-breath-for-good` (the first Huge If True-style edit, 2026-09-28).

## Cutting the time on the next video without losing quality (Ben, 2026-09-29: "get the time down... without making the quality any worse")
1. **Dialogue lock first.** Send a dialogue-only version, take Ben's notes (takes, stumbles, glances), fix, and get his OK BEFORE any final graphics render. Graphics are designed in parallel as stills. This video's cut changed ~6 times and each change sent dozens of finished graphics back to re-render.
2. **Review renders at 1080p (`--scale 1`), 4K only for the final.** A quarter of the pixels, roughly 3-4x faster, same on the review player.
3. **Faster renderer:** WebCodecs GPU encode + Blender for 3D heroes (next section).
4. **Reusable scene library:** move this video's kits (tongue, teeth/braces, bacteria/molecules, tonsils/throat, product studio, paper/headline treatments, chapter/name cards) into a shared `pipeline/motion/kits/`; Blender models too.
5. **At the shoot (Ben's choice):** a beam-splitter teleprompter on the lens removes the script glances at the source; a clap or "again" before a retake makes retakes exact.
6. **Resolve review renders from the 1080p proxies** (about 3x faster). v4d's review render was GPU-decoder-bound (81% GPU, 75% NVDEC) decoding 101 stacked 4K graphics: ~75 min vs 14 min for v4b. Make 1080p proxies of every scene file too (the snapshot step can write them) and link them before review renders.

## Rendering stack for the next video (discussed with Ben, 2026-09-29)
- Full-screen 2D scenes: keep the Canvas2D scene library, but encode in Chrome with WebCodecs (hardware H.264/HEVC) so frames never leave the GPU (G8); `skia-canvas` (Node, GPU Skia) is the no-browser alternative with the same drawing API.
- 3D hero shots (anatomy, products, microbes): Blender (Cycles/OptiX or Eevee on the 3090) for real subsurface scattering, depth of field, motion blur and materials. Needs Ben's OK to download (~350 MB, free), and Python (bpy) scripts, an exception to the Node-only rule to note in CLAUDE.md.
- Titles, name cards, chapter cards, lower thirds: Fusion templates inside Resolve (GPU, no render files, editable by Ben on his timeline).
- Not worth it: Remotion / Motion Canvas (browser-based, same bottleneck).

## Order of work that avoids most of the above (Huge If True-style edit)
1. Paper edit (keep ranges, whole-cut comprehension pass), fixes, tighten, retakes, gaze scan, all BEFORE any final graphics render.
2. `assemble --stage map`, `--stage audio`, transcribe `work/cut-audio16k.wav`, `--stage map` again (heard times), listen-check.
3. Scene groups render against the locked cut (anchors only). Any later dialogue change: announce it and re-render.
4. `score.mjs` (anchored), `assemble --stage full --split --snapshot <version>`, Resolve import, stems, finish, review render.
5. Look (contact sheet + rhythm-check) before publishing; publish with honest notes; answer every comment.
